## 五、Git配置管理
### 1 配置项识别
1. README.md
2. 项目章程
3. WBS 文档
4. 进度计划文档
5. 配置管理文档
6. 冲突过程记录
7. 实验总结报告

### 2 分支策略
- main：主分支，存放最终版本，受保护
- dev：开发汇总分支
- feature/*：文档/功能分支，如 feature-郭语洋、feature-李嵩泽

### 3 提交规范
- 格式：姓名拼音: 简要说明
- 示例：liminghao: 完成WBS三级分解

### 4 合并规则
1. 个人分支 → dev 分支
2. 冲突解决后 → 提交 PR
3. 配置管理员审核 → 合并到 main

## 六、代码冲突处理
实验中团队刻意模拟多人协同开发场景，我与组员同时对同一文档的同一段落进行不同内容修改，人为制造 Git 分支代码冲突。冲突产生后，我学习识别 Git 冲突标记，区分本地分支修改内容与远程分支已有内容，手动甄别保留有效文字、删除多余冲突标识，完成文档内容整合修正。整理完毕后重新进行本地提交、拉取主干最新版本、再次推送分支并完成合并。通过本次实操，我掌握了代码冲突产生的根本原因、冲突查看方式、手动解决冲突的步骤，同时总结出规避冲突的方法：开发前先拉取主干最新代码、按模块划分分支编辑、避免多人同时修改同一文件同一片段，熟练具备了团队协作中处理 Git 合并冲突的实操能力。
